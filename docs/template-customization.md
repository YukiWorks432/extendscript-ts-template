# テンプレート利用後の初期設定

新しいGitコピーで依存関係を導入し、編集を始める前に `pnpm run configure` を実行します。
初期設定後は `pnpm new` で最初のスクリプトを作成します。

```sh
pnpm install
pnpm run configure
pnpm new
pnpm typecheck
pnpm build
```

## 選択する項目と既定値

| 項目                         | 初期値・動作                                                |
| ---------------------------- | ----------------------------------------------------------- |
| プロジェクト名               | フォルダ名を初期値にし、`package.json` の `name` へ反映     |
| 使用アプリ                   | `aeft,ilst,phxs`。対応する5アプリから1つ以上を選択          |
| サンプル                     | 残す。削除を選ぶと、`example` とその登録を削除              |
| AI向け設定                   | 利用する。不要なら`AGENTS.md`・`.agents/`・`.codex/` を削除 |
| プロジェクトの初期バージョン | `package.json` の `version` を `0.1.0` に設定               |
| 作者の情報・支援先           | 配布元の `author` と`.github/FUNDING.yml` を削除            |
| リリース                     | 明示的な有効化条件を保ったままワークフローを維持            |

アプリIDは `aeft / ilst / phxs / idsn / audt` です。
アプリのフォルダ、`es.config.mjs` の登録、`package.json` の `build:<appId>` を揃えます。
追加アプリにも `pnpm add-app` と同じ型設定と雛形を作成します。
Animate・Premiere Proは両コマンドの対象外です。対応条件と実行経路は[公開契約](public-contract.ja.md#対応環境と互換補正)を参照してください。
共通コード、共通テスト、依存関係、ライセンス表記は維持します。

個別スクリプトのバージョンは `es.config.mjs` で管理します。
プロジェクトの初期バージョン設定によって、既存スクリプトの版を変更しません。

## 適用条件と反映前の確認

初回設定は、Gitで取得したコピーを編集する前に使うコマンドです。
Gitの未コミット変更（ステージ済みを含む）または未追跡ファイルがあれば、何も変更せず停止します。
Gitの状態を確認できないコピーでも停止します。
公開配布元を `origin` に設定したリポジトリには適用できません。

質問と検査を終えると、残すアプリと更新・作成・削除する対象を表示します。
未選択アプリや、削除を選んだサンプル・AI設定のディレクトリは、配下を含めて削除します。
最後の確認で `y` と答えた場合だけ反映します。
キャンセル、入力の終了、中断、事前検査の失敗では、ファイルを変更しません。
`package.json` の未知の項目、共通コード、ライセンス表記は維持します。

配布時のファイルとの内容照合は行いません。
Gitの確認では、コミット済みの独自変更やGitの除外対象まで初期状態と区別することはできません。
すでに編集を始めたプロジェクトでは、下記の手動設定を使ってください。

完了時は `package.json` に `templateConfigured: true` を記録します。
設定済みなら、未コミット変更の有無にかかわらず再実行してもファイルを変更しません。
設定後のアプリ追加には `pnpm add-app`、構成の変更には各ファイルの編集を使います。

保存時の入出力エラーなどで反映に失敗した場合は、Gitの差分を確認してから再開してください。
完了したことを示す項目は、他の変更が成功した後に保存します。

## 初期設定後

生成するREADMEには、プロジェクト名、実際に残したアプリ、作成・型検査・ビルドの手順を記載します。
具体的な開発手順は[導入ガイド](guides/getting-started.md)を参照してください。

GitHubの設定やGitの履歴、リモートは自動変更しません。
必要に応じて、次の項目を手動で確認してください。

- `main` の保護規則と必須CI
- リポジトリの説明文やトピック
- リリースを利用する場合の `RELEASE_AUTOMATION_ENABLED=true`

リリース用ワークフローは、上記の変数を設定して手動実行した場合に動きます。
有効化方法は[リリース手順](release-process.md)を参照してください。

## 手動で設定する場合

`pnpm run configure` は必須ではありません。
手動で整える場合は、プロジェクト名と版番号、対象アプリのフォルダ・登録・ビルド別名を編集し、
README、作者の支援先、AI向け設定を自分の用途に合わせて整理してください。
編集後に `pnpm typecheck` と `pnpm build --all` を確認します。

## 将来のテンプレート更新

`Use this template` で作成したリポジトリは、元のコミット履歴を引き継ぎません。
`upstream` の登録と更新方法の検討は、初期設定とは別の任意の作業です。
元の更新を確認して、自分のプロジェクトの変更と比較しながら必要な箇所を取り込んでください。
`package.json` などを一括で上書きすると、初期設定後の情報が失われるため注意してください。

配布元の保守方針は[リポジトリ運営方針](repository-operations.md)に記載しています。
