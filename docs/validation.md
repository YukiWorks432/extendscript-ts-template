# 検証環境と実機確認の記録

このページは、開発環境の導入条件、CI、過去のAdobe実機確認を区別して案内します。2026年11月4日に既存の証跡を整理したもので、実機試験の再実行結果ではありません。

## 現在の開発環境

導入条件の正本は[package.json](../package.json)です。

- Node.js: `^24.22.1`
- pnpm: `^12.16.1`
- TypeScript: `4.9.5`（ES3出力のため厳密指定）

[CI](../.github/workflows/ci.yml)はUbuntu上のNode.js 24系で、依存監査、固定ロックファイルによる導入、コード検査、型検査、Node.jsの回帰テスト、全件ビルド、整形と差分の検査を実行します。Adobeアプリを起動する検証ではありません。

文書整理の基点であるテンプレートのコミット `19e803b54ade1e5e7dbac643418758ed47c36e81` では、[CIの成功記録](https://github.com/YukiWorks432/extendscript-ts-template/actions/runs/41760373261)があります。このCI結果を、下記の実機試験と同じ生成物の結果として扱いません。

## 雛形生成と実機確認

初期設定済みのアプリは `aeft`、`ilst`、`phxs` です。`pnpm add-app` はこれらに加えて `idsn`、`ppro`、`anmt`、`audt` の雛形生成に対応します。型定義と設定の生成が可能であることと、各製品の実機確認は別の範囲です。

### テンプレートと利用側の検証

[compat 1.0.0の出荷判断](https://github.com/YukiWorks432/extendscript-compat/blob/8561c298e9ea56f8143cb8c2bd2430a9e497d4b3/docs/release-1.0.0.ja.md)と[集計原記録](https://github.com/YukiWorks432/extendscript-compat/blob/c313a4c5305f947bfcf996d5ff743858aa4c6487/docs/evidence/2026-11-04/v1-release/results.json)を根拠とします。

- compatのJSON修正統合後 `9f180f4` を使った公開テンプレートの一時コピーで、全4本のビルドと、4製品それぞれの共通検査48/48項目が成功しました。当時の環境はNode.js 24.22.1、公開テンプレート側のpnpm 12.16.1でした。
- 同じcompat候補と公開済み0.4.0を比較した利用側の一時コピーでは、両版で全88本をビルドし、4製品の共通検査48/48項目が成功しました。代表操作はAE 10/10、Illustrator 7/7、Photoshop 4/4でした。
- 利用側の比較では、両版へTerserの `ie8: true` を追加し、当時の `conditionals: false` を維持しました。元の利用側ソースは変更していません。代表操作は結果表示の待機を検査用に差し替えたもので、ダイアログ描画やクリックの検査ではありません。Premiere専用の利用側スクリプトはありません。

ここでいう `9f180f4` はcompat側のコミットです。現在のテンプレートのビルド基盤や、同じ件数の任意のスクリプト全体を実機確認した結果ではありません。

### ランタイムと追加補正の検証

- compat `9f180f4` では、通常版と圧縮版を別々の再起動後に初回導入しました。AE・Illustrator・Photoshopは各707/707項目が成功しました。Premiereの文字列列挙3項目は、その後の修正で確認しています。
- compatのPremiere修正 `e7326e8` では、Premiereは通常・圧縮と0.4.0共存の4条件、Illustrator・Photoshopは通常・圧縮、AEは圧縮で各714/714項目が成功しました。PremiereのJSX直接実行も4条件で各714/714項目が成功しました。修正後の確認は同じエンジンの状態を復元して行った条件を含み、全条件で個別に再起動した確認ではありません。詳細は上記の出荷判断と原記録を参照してください。
- 依存するcompat 1.1.0は、1.0.0から配布ランタイムを変更していません。追加した `for` 初期化部分の `in` 演算子の補正は、AE 26.5x89 / ExtendScript 4.5.6で15例の期待結果との一致を確認しています。元の利用側JSXの確認は全体の構文解析までで、レイヤー操作は実行していません。[1.1.0の変更点と検証範囲](https://github.com/YukiWorks432/extendscript-compat/blob/8561c298e9ea56f8143cb8c2bd2430a9e497d4b3/docs/releases/1.1.0.ja.md)と[実機原記録](https://github.com/YukiWorks432/extendscript-compat/blob/c72af07c8e78ac067b1ee9b314c6db64bf6722a0/docs/evidence/for-initializer-ae-26.5.json)を参照してください。

## 確認範囲の限界

上記の証跡は、当時のコミット・生成物・製品版・実行経路に対する結果です。現在のテンプレートとcompatの全機能を、すべて同じ最終生成物で実機検証したという意味ではありません。Premiereの記録も、Premiere全体をcompatの保証対象に追加するものではありません。

InDesign・Animate・Audition、macOS、表にないAdobe製品版について、このページで参照した証跡から実機確認済みとは判断しません。API固有の制限は[ポリフィル](polyfills.md)からcompatの公開契約と対応表を参照してください。

新しい利用側の操作や対象環境は、その利用先で必要な項目を確認してください。既存の証跡は対象コミットとハッシュを保持したまま参照し、後の変更による実測結果へ読み替えません。
